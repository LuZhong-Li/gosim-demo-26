# 调试指南

> 目标：快速定位问题。依据：docs/plans/03-分层与代码结构.md 4.5。

## DEBUG_MODE 开关

- 修改 `config.py` 中 `DEBUG_MODE = True`。
- 开启后：打印调用链路、入参出参、数据快照、完整堆栈。
- 关闭后：只输出 WARNING/ERROR 级别日志。

## trace 查看方法

- trace 文件：`demo/output/trace.jsonl`，每行一个 JSON 对象。
- 类型枚举：`prompt` / `api_call` / `tool_call` / `workflow_run` / `human_intervene`。
- 查看示例：

```powershell
Get-Content demo/output/trace.jsonl
```

- 校验：`python tools/check_trace.py demo/output/trace.jsonl`（Phase2 起可用）。
- 注意：trace 由程序自动写入，禁止手动编辑。

## 单步调试方法

1. 开 `DEBUG_MODE=True` 复现，收集调用链路和报错栈。
2. 按「现象 -> 先查」定位模块：

| 现象 | 先查 |
| --- | --- |
| 写操作失败 | 权限（P001）-> 规则（R001）-> 存储锁 -> 审计日志 |
| xlsx 打不开/损坏 | 存储错误码（S001/S002）-> 备份文件 |
| trace 不完整 | `tools/check_trace.py` + 拦截器日志 |
| 环境跑不起来 | `tools/check_env.py`（Python 版本、依赖） |
| 数据被改错 | `audit_log` 的 `before_snapshot` 回溯 |

3. 跑该模块对应单元测试确认修复：`pytest tests/unit/test_<模块>.py -v`。
4. 修复后检查 `audit_log` / `trace.jsonl` 是否留痕，再跑集成测试。
