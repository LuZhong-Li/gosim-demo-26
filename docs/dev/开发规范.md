# 开发规范

> 目标：统一命名与分层约定，保证问题定位快、修改影响范围小。
> 依据：docs/plans/03-分层与代码结构.md。

## 命名规范

- 文件：小写下划线，如 `service_bus.py`、`check_env.py`。
- 工作表名：小写 + 下划线，统一在 `constants.py` 注册（如 `workflow_runs`），禁止硬编码。
- 函数：动词开头小写下划线，如 `check_permission`、`append_row`。
- 测试文件：`test_<模块>.py`，放 `tests/unit` 或 `tests/integration`。
- 错误码：大写前缀 + 三位数字（S/P/R/A/W + 001）。

## 分层依赖约定

自下而上依赖，禁止反向依赖：

| 层 | 目录 | 可 import | 禁止 import |
| --- | --- | --- | --- |
| 底层 | `storage/`、`domain/` | 标准库、openpyxl、pydantic、`errors.py`、`constants.py` | `services/`、`core/`、`api/`、`agent/` |
| 中层 | `services/`、`core/` | `storage/`、`domain/`、`errors.py`、`constants.py`、`config.py` | `api/`、`agent/` |
| 上层 | `api/`、`agent/` | `core/service_bus.py`、`errors.py` | 直接调 `storage/`、`domain/`（必须走门面） |

约定：

1. 上层所有操作走 `core/service_bus.py` 统一门面，不直接调用零散服务。
2. 新模块只能 import 本层及以下层，按上表检查。
3. 涉及新工作表时，先在 `constants.py` 注册表名再建表。
4. 一个函数只做一件事，不超过 50 行。

## 错误处理规范

- 所有业务错误抛 `GXError(code, message, module, context)`（定义在 `errors.py`）。
- 固定流转链路：`raise GXError` -> 拦截器捕获 -> 写 `audit_log`（success=false）-> 写 `trace.jsonl` -> CLI 统一格式化输出 `[code] message`。
- 不吞错误：任何 `except` 必须重抛或记录后再抛。
- 写操作一律走审计拦截器，业务代码不直接写存储。

| 前缀 | 模块 | 示例 |
| --- | --- | --- |
| S | 存储 | `S001` 文件不存在、`S002` 工作表不存在 |
| P | 权限 | `P001` 权限拒绝 |
| R | 规则 | `R001` 规则违规 |
| A | 审计 | `A001` 审计写入失败 |
| W | 工作流 | `W001` 工作流运行错误 |
