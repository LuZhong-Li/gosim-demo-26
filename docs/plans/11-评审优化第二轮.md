# 评审优化第二轮 Implementation Plan（细化版）

> **For agentic workers:** 执行时沿用本仓库“小切片提交 + 验证闭环”习惯，用
> `- [ ]` 跟踪进度；禁止改写 `main` 的初赛冻结基线。

**Goal:** 在不动初赛提交物与 trace 基线的前提下，先补齐工程可信度（P0），再在
`codex/dev` 上孵化 Agent 可插拔、组织经验库、trace 可读化三类实验能力。

**Architecture:** P0 验证后可进入 `main`；P1/P2 只在 `codex/dev` 开发。Agent 仅
改造上层解析层，不改 `ServiceBus`、`PermissionService`、`RuleService`；trace 顶层
8 字段与 5 种 type 冻结，扩展信息只进 `detail` 子字段。

**Tech Stack:** Python 3.11–3.14、pytest、ruff、typer；`codex/dev` 可选
OpenAI 兼容 LLM 适配器（默认关闭）。

**Spec:** 本文档 + [09-初赛代码优化与提交保护.md](09-初赛代码优化与提交保护.md)
（红线）+ [10-评审优化第一轮.md](10-评审优化第一轮.md)（第一轮实施状态）。
外部参考：mioa-harness、OpenCollab 的对比分析，只借鉴模式，不照搬架构。

## Global Constraints

- `main` 永远保留初赛冻结基线；正式 trace 10 条、xlsx 基线、demo 流程不得改变。
- 所有 P1/P2 实验只在 `codex/dev` 开发，评审通过前不得合并 `main`。
- trace 顶层字段与 type 枚举禁止修改；`check_trace.py` 校验规则不变。
- Agent 记忆属于上层思考辅助，不得参与权限/规则/业务判定。
- 测试一律使用 `tmp_path`，不得改写 `demo/output/trace.jsonl`、
  `demo/seed-workbook.xlsx`。
- 每步小切片提交，文档与代码分离；push 由用户手动执行。

class MemoryLayer(str, Enum):

    reason: str = ""

## 7. 风险与可行性控制

| 风险 | 控制方法 |
|---|---|
| ruff 自动修复误改逻辑 | 只启用 E/F/I/UP；提交前 `git diff` 逐块确认；全量 pytest |
| CI 的 Ubuntu 与本地 Windows 行为差异 | 测试只依赖 `tmp_path` 与 openpyxl；不运行 demo 脚本 |
| `run_demo` 复验污染正式 trace/xlsx | 复验后必须 `git restore --source=HEAD -- demo/output/trace.jsonl demo/seed-workbook.xlsx` |
| Agent 记忆误入业务表 | 路径 `demo/output/agent_memory.jsonl` 独立且已 gitignore；规则/权限不 import memory |
| request_id 改变 demo 输出 | 默认关闭；只测试显式开启路径 |
| trace replay 输出破坏源文件 | 渲染函数纯内存，CLI 显式 `--out`，从不写 `--source` |
| LLM 依赖进入 main | `openai` 只放在 optional extra `llm`，`main` 不安装 |
