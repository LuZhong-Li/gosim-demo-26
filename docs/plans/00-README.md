# GX-Sheet 项目计划总览

> 入口文件：先读「第一部分 · 项目总览与总体路线」建立全局认知，再按编号文件深入细节。本文件分三部分。

## 第一部分 · 项目总览与总体路线

### 1.1 项目是什么

- 项目：GOSIM Create 2026 初赛作品
- 名称：GX-Sheet：基于电子表格模拟 GitHub 组织管控与自动化 Agent 原型
- 形态：概念验证原型（非生产级产品）
- 数据底座：xlsx 电子表格 = **唯一持久数据源**（Workbook = 组织，Sheet = 资源集，行 = 实体）
- 交互入口：Mock Agent 自然语言 → 内部 CLI/API

### 1.2 要交付的四大能力（最小语义）

| 能力 | 最小交付 |
| --- | --- |
| 组织权限 | members/teams/roles + 写前校验，readonly 用户写被拒 |
| Rulesets | pull_requests 模拟 PR，2 条规则（审批 ≥ 1、required-check） |
| 审计留痕 | audit_log 只追加 + 基础哈希链 |
| Actions | 最小步骤 runner（shell/python/http）→ workflow_runs |

### 1.3 可行性保障（三条硬约束）

| 约束 | 做法 |
| --- | --- |
| 零外部依赖 | 纯本地 Python 库；不用在线 LLM/API；无需密钥，评审环境开箱即用 |
| 最小范围 | 只做可演示链路；非目标明确；越界功能进 FUTURE.md |
| 可验证 | 每阶段有验证命令 + pytest + 审计/trace 留痕，提交前可自检 |

### 1.4 总体路线与工时（执行顺序）

| 阶段 | 内容 | 预估工时 | 退出标志 |
| --- | --- | --- | --- |
| Phase0-1 | 存储 + 领域模型 + 权限 + 成员 CLI | 4-6 天 | 能生成工作簿、管理成员、权限拒绝 |
| Phase2 | 审计 + Trace + PR + Rulesets | 3 天 | 核心管控闭环，trace 能力完成 |
| Phase3-4 | Actions 工作流 + 完整 CLI + Mock Agent | 4-5 天 | 工作流自动化 + 自然语言交互 |
| Phase5 | 一键 demo + 文档 + 提交物 | 2 天 | 三项提交物就绪 |

合计约 13-16 天，落在 9.7-9.20 研习营窗口内；每阶段预留半天缓冲，9.18 前锁定「权限 + 审计 + 规则」三件套。

### 1.5 验收红线（做完了才叫完成）

创建成员 → 创建 PR → 权限拦截 → Rulesets 阻止非法合并 → 运行 Workflow → 审计 + trace 全部留存。

## 第三部分 · 使用约定

### 3.1 阅读顺序

先读 01 建立定位，再按 02-08 深入；开发时对照 04，排期看 05，提交前看 07。

### 3.2 更新规则

- 只改对应编号文件，不合并回一个总文件；
- 跨文件引用写「文件名 + 小节号」（如「见 05-排期与工程化保障 7.2」），不写旧章节号；
- 改完文件后，同步更新 00 索引里该文件的「内容」摘要；
- 决策有变化：先更新 08，再把结论同步到受影响文件。

### 3.3 写法要求

- 尽量给出「验证命令」或「可勾选项」，少写空泛描述；
- 命令、文件名、工作表名一律用反引号包裹；
- 删除内容前确认没有被其他文件引用。
