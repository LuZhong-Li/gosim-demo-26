# 04 · 里程碑任务

## 里程碑任务细化（拆到单人可执行粒度）

> 约定：每阶段按「子任务 → 产出 → 完成标志 → 验证命令」落地；后一阶段依赖前一阶段；每阶段结束都要满足《01-项目定位与执行策略》的 DoD（可运行、可测试、可演示、有留痕）。CLI 命令名以 Phase4 最终确认为准，下列为验证示例。

### Phase0：项目骨架 + 存储层 + 种子工作簿（2-3 天）

> 前置：Python 3.11-3.12、git 已安装；代码根按《08-待确认决策点》确认为 `gosim-demo-26/`。

| 子任务 | 产出 | 完成标志 |
| --- | --- | --- |
| 1. 创建完整分层目录，初始化 git 仓库 | `gosim-demo-26/` 目录骨架 | 目录与空文件就位 |
| 2. 编写 requirements.txt + constants.py + config.py + errors.py + .gitignore | 根目录工程文件 | 依赖可一次装完，常量/错误码就位 |
| 3. 定义 BaseStorage 抽象接口 | `src/gx/storage/base.py` | 接口方法定义完成 |
| 4. 实现 LocalXlsxStorage + 内存写锁 | `src/gx/storage/xlsx.py` + `lock.py` | 能读写 xlsx 文件、追加行 |
| 5. 编写种子工作簿生成脚本 | `demo/init_seed.py` | 运行后自动生成带全部工作表的 xlsx |
| 6. 存储层单元测试 | `tests/unit/test_storage.py` | pytest 全部通过 |

验证命令：

```
python tools/check_env.py
python demo/init_seed.py
pytest tests/unit/test_storage.py -v
```

预期：生成 `demo/seed-workbook.xlsx`，打开能看到所有空工作表。

### Phase1：领域模型 + 权限引擎 + 成员管理 CLI（2-3 天）

> 模型清单：Member、Team、Role、PullRequest、Workflow、WorkflowRun、AuditLog、RuleSet（与 03 的 4.1 目录注释一致）。

| 子任务 | 产出 | 完成标志 |
| --- | --- | --- |
| 1. 编写全部 pydantic 领域模型 + 枚举 | `src/gx/domain/models.py` + `enums.py` | 成员、团队、角色等模型定义完成 |
| 2. 实现权限校验服务 + 角色权限矩阵 | `src/gx/services/perms/` | 输入用户 + 操作 + 资源能返回对错 |
| 3. 实现成员 / 团队增删改查 CLI 命令 | `src/gx/api/cli.py` | 命令行能加用户、改角色 |
| 4. 权限模块单元测试 | `tests/unit/test_perms.py` | 合法操作通过、非法操作拒绝 |

验证命令：

```
gx member add alice member
gx member set-role alice readonly
pytest tests/unit/test_perms.py -v
```

预期：`members` 表新增 alice；readonly 用户执行写操作被拒绝（P001）。

### Phase2：审计拦截器 + Trace 输出 + PR + Rulesets（3 天）

> 本阶段完成后 trace 能力即就绪，对齐 00 的「核心闭环版」MVP；审计行字段与拦截器逻辑见 02 的 3.2。

| 子任务 | 产出 | 完成标志 |
| --- | --- | --- |
| 1. 实现审计拦截器 + 哈希链基础版 | `src/gx/services/audit/interceptor.py` | 所有写操作自动追加 audit_log 行 |
| 2. 嵌入 trace.jsonl 自动输出 + 统一日志 | `src/gx/services/audit/trace.py` | 操作生成 trace，ERROR 自动留痕 |
| 3. 实现 PR 模型 + 创建 / 合并编排 | `src/gx/domain/models.py` + `src/gx/core/service_bus.py` | 能创建 PR、执行合并 |
| 4. 实现 Rulesets 规则引擎 | `src/gx/services/rules/service.py` | 无审批的 PR 合并被拦截 |
| 5. 集成测试 | `tests/integration/test_full_chain.py` | 完整操作链路跑通 |

验证命令：

```
gx pr create --title "demo change"
gx pr merge 1                  # 预期被 R001 拦截（无审批人）
gx pr approve 1 alice
python tools/check_trace.py
pytest tests/integration/test_full_chain.py -v
```

预期：无审批 PR 合并被拦截；approve 后合并逻辑就绪；`audit_log` 与 `trace.jsonl` 均有成功/失败记录；required-check 联动留到 Phase3 验证。

### Phase3：Actions 工作流 Runner（2-3 天）

> 工作流步骤最小子集：shell / python / http（见 01 的 1.2）；required-check 读取该 PR 最新一条 `workflow_runs`，状态为成功才放行（见 02 的 3.4）。

| 子任务 | 产出 | 完成标志 |
| --- | --- | --- |
| 1. workflow 定义解析 + 步骤执行器 | `src/gx/services/actions/runner.py` | 能按顺序执行 shell/python 步骤 |
| 2. workflow_runs 运行记录模型 | `src/gx/domain/models.py` | 每次运行生成一条运行记录 |
| 3. 手动触发 + 数据变更触发 | `src/gx/services/actions/trigger.py` | CLI 调用能触发工作流 |
| 4. 与 Rulesets 联动：required-check 校验 | `src/gx/services/rules/workflow_check.py` | 工作流失败则阻止 PR 合并 |
| 5. 工作流单元 / 集成测试 | `tests/unit/test_actions.py` + `tests/integration/test_workflow.py` | 运行记录落表、失败拦截 |

验证命令：

```
gx workflow run ci-check        # 定义一个可失败的工作流并运行
gx pr merge 1                   # 预期被 required-check 拦截
pytest tests/integration/test_workflow.py -v
```

预期：`workflow_runs` 新增失败记录；工作流失败时 PR 合并被 required-check 拦截。

### Phase4：完整 CLI + Mock Agent 自然语言层（2 天）

> 典型自然语言 → CLI 映射（完整清单写入 `agent/AGENTS.md`）：

| 自然语言 | 映射 CLI |
| --- | --- |
| 添加成员 bob 为 member | `gx member add bob member` |
| 运行工作流 ci-check | `gx workflow run ci-check` |
| 创建 PR demo change | `gx pr create --title "demo change"` |

| 子任务 | 产出 | 完成标志 |
| --- | --- | --- |
| 1. 补齐全部业务 CLI 命令（只调 core 门面） | `src/gx/api/cli.py` | 所有功能都有对应命令 |
| 2. 实现 mock_nl_parser 字符串匹配转 API | agent/mock_nl_parser.py | 输入 “添加成员 bob” 能调用对应 CLI |
| 3. 编写 AGENTS.md 技能说明 | agent/AGENTS.md | 列出所有支持的自然语言指令 |
| 4. mock_nl_parser 单元测试 | `tests/unit/test_mock_parser.py` | 典型自然语言映射正确 |

验证命令：

```
python agent/mock_nl_parser.py "添加成员 bob 为 member"
python agent/mock_nl_parser.py "运行工作流 ci-check"
python agent/mock_nl_parser.py "创建 PR demo change"
pytest tests/unit/test_mock_parser.py -v
```

预期：自然语言能翻译为对应 CLI 调用并执行。
