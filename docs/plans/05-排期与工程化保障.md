## 工程化落地保障（避免低级问题卡壳）

> 目标：评审环境开箱即用、报错可定位、提交前可自检；能用命令自动检查的就不靠记忆。

### 7.1 环境与依赖锁定

- Python 版本约束 3.11-3.14（`>=3.11,<3.15`），写入 README 与 `pyproject.toml` 的 `requires-python`；
- 依赖最小集固定版本，且全部为本地纯 Python 库，无需外部 API 密钥：

```
openpyxl==3.1.5   # xlsx 读写
pydantic==2.13.5   # 领域模型
typer==0.12.5     # CLI
pytest==8.3.2     # 测试
```

安装与运行入口：

```
pip install -r requirements.txt
python demo/init_seed.py
```

> 建议用虚拟环境：`python -m venv .venv` 后再安装，装完跑一次 `python tools/check_env.py` 确认环境就绪。

### 7.2 提交前自检（preflight）

一键自检，任一失败即不提交：

```
python tools/check_env.py
pytest -q
python tools/check_trace.py demo/output/trace.jsonl
```

| 脚本 | 检查项 |
| --- | --- |
| `check_env.py` | Python 版本、依赖是否齐全 |
| `pytest -q` | 单元 + 集成测试全部通过 |
| `check_trace.py` | jsonl 每行合法、必填字段齐全、含人工干预记录 |

- `tools/debug_helper.py`：排查时打印指定工作表内容、审计最新记录。

> 任一失败即不提交：`check_env.py` 失败先装依赖，`pytest` 失败定位到失败用例，`check_trace.py` 失败先重跑 demo 生成 trace，修完重跑自检。

### 7.3 统一错误处理流程

所有业务错误抛 `GXError(code, message, module, context)`（错误码表见《03-分层与代码结构》4.4），并按固定链路流转：

```
raise GXError(...)
   → 拦截器捕获
   → 写 audit_log（success=false + error_msg）
   → 写 trace.jsonl（ERROR 同步留痕）
   → CLI 统一格式化输出 [code] message
```

- 不吞错误：任何 `except` 必须重抛或记录后再抛；
- 演示阶段人工干预通过 `log_human_intervene(desc)` 留痕。

**CLI 输出示例**：

```
$ gx pr merge 1
[R001] 规则违规（module=rules, resource_id=1）
```

### 7.4 代码与提交约定

| 约定 | 要求 |
| --- | --- |
| 入口 | 业务层只调 `core/service_bus.py` 门面，不直接碰存储与零散服务 |
| 写操作 | 一律走审计拦截器 |
| 常量/配置 | 常量放 `constants.py`，可调参数放 `config.py` |
| 日志 | 统一 `logging` 分级，ERROR 自动写入审计和 `trace.jsonl` |
| 调试 | `config.DEBUG_MODE` 开启详细调用链路与数据快照 |
| 提交 | 每个 Phase 至少一次提交，消息带前缀，如 `feat(phase1): 成员管理 CLI` |
