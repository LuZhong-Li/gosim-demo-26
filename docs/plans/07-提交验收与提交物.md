# 07 · 提交验收与提交物

## 最终提交校验清单（提交前逐项打勾）

> 使用方式：提交前逐项勾选；有「校验命令」的条目先跑命令再勾选。全部通过后再去提交页填写三个链接。

> 三项提交物分别对应第十节的 10.2（仓库）、10.3（trace）、10.4（视频），本清单全勾后再去填写链接。

### 工程验收

- [ ] 项目本地可运行：`gx --help`（或 `python -m gx --help`）正常输出，**不需要任何 API 密钥**
- [ ] pytest 测试套件完整可执行：`pytest -q` 全绿
- [ ] 一键 demo 脚本跑通完整链路：创建成员→创建 PR→权限拦截→Rulesets 阻止非法合并→执行 Workflow→审计 + trace 全部留存
- [ ] `demo/seed-workbook.xlsx` 预置样例；`docs/specs`、`agent/AGENTS.md` 文档齐全

### GitHub 仓库

- [ ] 仓库设置为 **Public**
- [ ] README 写明：Python 版本、依赖安装命令、**一键启动命令**、演示说明
- [ ] 根目录有 `requirements.txt`
- [ ] 包含完整源码、seed 工作簿、一键 demo 脚本
- [ ] 链接是仓库主页 URL，不带 `.git` 后缀

### 生产轨迹 trace.jsonl

- [ ] 文件在仓库 `demo/output/` 目录下
- [ ] 格式是 `.jsonl`，每行一个 JSON 对象（`python tools/check_trace.py demo/output/trace.jsonl` 通过）
- [ ] 包含：prompt、API 调用、工具调用、工作流运行、人工干预 等类型记录
- [ ] 提交链接是 **Raw 原始链接**（点 Raw 后复制地址，非 blob 链接）
- [ ] 无痕模式打开链接能直接下载文本

### Demo 视频

- [ ] 时长 **3-5 分钟**
- [ ] 内容覆盖：启动 → 成员管理 → 权限拦截 → PR 规则拦截 → 工作流执行 → 审计查看
- [ ] 上传后设置公开，无痕模式能直接播放
- [ ] 视频清晰，命令和输出文字可见

### 提交前最后一步

一次性跑完自检（见《05-排期与工程化保障》7.2）：

```
python tools/check_env.py
pytest -q
python tools/check_trace.py demo/output/trace.jsonl
```

## 大赛提交物实现方案（提交页三项输入：GitHub 仓库链接 / trace.jsonl 链接 / Demo 视频链接）

> 提交页三个输入框：① GitHub 仓库链接 ② 生产轨迹链接（trace.jsonl） ③ Demo 视频链接。下面给出实现逻辑、产出步骤与验收标准。

### 10.1 提交物速查

| 提交项 | 内容 | 链接要求 | 填入输入框 |
| --- | --- | --- | --- |
| 源码 | Public 仓库 | 仓库主页 URL，不带 `.git` | GitHub 仓库 |
| 生产轨迹 | `demo/output/trace.jsonl` | Raw 原始下载链接 | 生产轨迹链接 |
| Demo 视频 | 3-5 分钟演示 | 公网可直接播放 | Demo 视频 |

**提交操作顺序**：跑 demo 生成 trace → 推送到 GitHub → 复制仓库 URL → 打开 trace 文件复制 Raw 链接 → 上传视频拿公开链接 → 到提交页填三个输入框。

### 10.2 GitHub 仓库链接

- 产出步骤：
  1. 将完整项目代码推送到 GitHub，仓库设为 **Public 公开**；
  2. 复制仓库主页浏览器地址栏 URL（**不要带末尾 `.git`**）；
  3. 填入平台 “GitHub 仓库” 输入框。
- 产物内容：完整源码、`demo/seed-workbook.xlsx`、`requirements.txt`、README、一键 demo 脚本、`demo/output/trace.jsonl`。
- 验收：他人 clone 后本地无需密钥，执行一键脚本即可运行。

### 10.3 生产轨迹链接 trace.jsonl

> ⚠️ trace 记录**系统 Agent 演示运行轨迹，不是开发过程日志**；格式 `.jsonl`，每行一个 JSON 对象。

- 实现逻辑：审计拦截器切面自动写 `demo/output/trace.jsonl`，**禁止手动编辑**；人工干预走 `log_human_intervene(desc)` 写入 `human_intervene` 类型。
- 产出步骤：
  1. 运行 `demo/run_demo.sh`（Windows 用 `demo/run_demo.bat`）跑完整链路，自动生成 `demo/output/trace.jsonl`；
  2. 将生成的 `trace.jsonl` 提交上传至 GitHub 仓库；
  3. 在 GitHub 网页打开该文件，点击右上角 **Raw（原始）** 按钮，复制浏览器地址栏 Raw 链接；
  4. 将 Raw 链接填入平台 “生产轨迹链接” 输入框。
- 验收：`python tools/check_trace.py demo/output/trace.jsonl` 通过；包含 prompt、api_call、tool_call、workflow_run、human_intervene 等类型记录；Raw 链接公网可访问、无需登录。

### 10.4 Demo 视频素材（3-5 分钟）

- 产出步骤：
  1. 录制一键 demo 脚本执行过程（覆盖 CLI / Agent 交互画面），完整链路：创建成员→创建 PR→权限拦截→Rulesets 阻止非法合并→执行 Workflow→审计 + trace 留存；
  2. 时长控制在 3-5 分钟，命令与输出清晰可见；
  3. 上传至支持公网访问的平台（如 Bilibili / YouTube 等），复制公开可访问的视频链接；
  4. 将视频链接填入平台 “Demo 视频” 输入框。
- 验收：链接可公网直接播放，内容覆盖完整演示链路。
