## S2 细化框架：Actions 能力补齐

### 对照

- 官方方向词：有向图 / Cron / 环境（14 §1.2 行 05）。
- 仓库现状：顺序 steps 执行 + 手动触发 + 按 PR 关联 + disabled 拦截（W001）
  + `workflow_runs` 记录；Web 有运行按钮，无运行日志页。

### 缺口与拟议最小切片（样例后展开，全部 TDD）

| 切片 | 内容 | 待确认锚点 |
| --- | --- | --- |
| S2-1 | `Workflow` 模型/种子扩展：`jobs`（含 `needs`）、`cron` 表达式、`env` 字段；兼容旧 seed | C2 表达位置 |
| S2-2 | Runner DAG：按 `needs` 拓扑执行，前置失败短路 | C5 并行度 |
| S2-3 | Cron：`next_run` 计算 + 触发命令（`gx workflow run --trigger cron` / API） | C1 是否真实调度 |
| S2-4 | env 注入：workflow/job/step 级环境变量传入 shell/python/http 步骤 | C3 保密与持久化 |
| S2-5 | Web：工作流详情与运行日志（`workflow_runs` 列表 + 输出查看） | C4 日志落点 |
| S2-6 | 矩阵扩展 + 文档 + 收尾验证 | — |

### 决策点

- C1：被测环境是否驱动真实调度器？若无真实时钟，Cron 最小交付 =
  「解析 cron 表达式 + 计算 `next_run` + 手动触发时可测」，不实现后台定时线程。
- C2：DAG 放哪——`workflows.steps` JSON 内扩展 `jobs` vs 新增
  `workflow_jobs` 工作表（8-Sheet 数据底座会变，属破坏性决策）。
- C3：env 值是否需持久化/脱敏；演示种子明文 vs 运行日志屏蔽。
- C4：运行日志存哪——`workflow_runs.detail` 扩展 vs 新工作表。
- C5：是否需要并行 job；若不需要，DAG 最小实现退化为
  「顺序 + 拓扑依赖校验」（先做此保守版）。

### 退出标准

- 方向词三项（有向图/Cron/环境）均有可测实现 + 集成测试；
- Web/API 可演示 DAG 失败短路、cron 计算、env 注入；
- limitation 表 Actions 行更新；全量回归 + ruff + 正式 trace 10 条未动。

### 保底

- 9/15 样例仍不可得：按 14 §2.1 的保守原则推进 S2-1..S2-2（DAG 顺序语义）
  并单独决策，不做 Cron/并行猜测。

## S3 细化框架：组织权限收敛

### 对照

- 官方方向词：层级组织 / 行字段权限 / Rulesets + CODEOWNERS / 合规导出
  （14 §1.2 行 06）。
- 仓库现状：roles 表唯一来源（S3-A）、成员/团队唯一性、防提权、PR 审批身份
  校验、审计哈希链 + 合规导出；limitation #1「团队权限并集提权」未修。

### 缺口与拟议最小切片（样例后展开，全部 TDD）

| 切片 | 内容 | 待确认锚点 |
| --- | --- | --- |
| S3-1 | `teams` 层级模型（parent/child）+ 成员唯一归属；种子与 fixture 兼容 | C8 层级深度 |
| S3-2 | 权限解析去并集：默认拒绝 + 明确解析规则（自身角色、直属团队、上级团队） | C6 解析规则 |
| S3-3 | CODEOWNERS 必需审批人：规则新增 `required_reviewers`（或 CODEOWNERS 映射） | C7 表达位置 |
| S3-4 | 行/字段级可见性：read 路径按团队过滤（只能看本部门）+ 审计留痕 | C9 粒度 |
| S3-5 | Web 适配 + 验收矩阵扩展 + 文档 + 收尾验证 | — |

### 决策点

- C6：团队角色解析规则。并集语义移除后选型：成员自身角色 + 直属团队角色；
  是否上溯 parent（若做层级组织）。**默认假设：不跨团队上溯、不继承他成员角色，
  避免 P001 判定过宽**。
- C7：CODEOWNERS 表达位置——`rulesets.config` 扩展 vs 新表 vs
  「仓库根文件」映射（GitHub 语义是 `.github/CODEOWNERS`，本项目无真实文件系统，
  需映射为表格/规则行）。
- C8：层级深度：两层（team→child）还是任意树。默认先两层，够用即停（YAGNI）。
- C9：行/字段权限粒度：「行级（只能看本部门成员行）」先行；字段掩码仅当样例
  明确要求。

### 退出标准

- limitation #1 关闭，P001 判定与权限矩阵规格一致；
- CODEOWNERS 必需审批人有集成测试；字段/行过滤有集成测试；
- 正式 trace/xlsx 基线未动（权限语义变更用独立 workbook 验证，重录留到收尾）。

### 风险与边界

- 修改权限解析会改变 P001 行为与历史测试断言：先写失败测试，再同步改
  limitation 与相关测试；不在样例确认前动正式 demo 基线。
- 若样例表明 01/02/03（认证/仓库生命周期/Issue）为必做范围，立即触发
  14 §2.2 的 D2 复审，S2/S3 让位排序。
