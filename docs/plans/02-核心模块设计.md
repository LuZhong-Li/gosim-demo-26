# 02 · 核心模块设计

## 核心模块落地增强（补充具体实现思路）

### 3.1 Storage 存储层

**职责**：唯一接触 openpyxl 的地方，上层只依赖 `BaseStorage`，不感知底层文件格式。

**抽象接口固定核心方法（7 个）**：

```
class BaseStorage:
    def create_workbook(self, path: str):  # 新建空工作簿（种子脚本用）
    def get_sheet(self, sheet_name: str) -> list[dict]:  # 读整表
    def append_row(self, sheet_name: str, row: dict):   # 追加行（审计用）
    def update_row(self, sheet_name: str, row_id: int, data: dict):  # 更新行
    def add_sheet(self, sheet_name: str, columns: list[str]):  # 新建工作表
    def save(self):  # 落盘（写操作后立即调用）
    def lock(self):  # 写锁，防止并发写冲突
```

**LocalXlsxStorage 实现要点**：

- `create_workbook(path)` 新建空文件，`__init__(path)` 加载已有文件；首行作为表头做字段映射；
- 写操作通过 `with storage.lock():` 加内存锁，写后立即 `save()`；
- 错误映射到统一错误码：文件不存在抛 `GXError("S001", ...)`，工作表不存在抛 `GXError("S002", ...)`；
- 工作表名统一从 `constants.py` 读取，禁止代码里硬编码字符串。

**接口约定**：

- `row_id`：表头为第 0 行，`row_id` 从 0 开始的数据行序号；
- `get_sheet` 返回 `list[dict]`，每行 dict 的键 = 表头列名；
- `lock()` 用 `@contextmanager` 实现，业务代码统一 `with storage.lock():` 包裹写操作；
- `update_row` 只允许改普通数据表，禁止指向 `audit_log`（审计只能追加）。

### 3.2 审计拦截器 + Trace 输出

**职责**：全局唯一写入口；业务代码不直接调 storage 写数据，所有写操作必须经过 `audit_interceptor(context)`。

**audit_log 行字段**（只追加，禁止 update/delete 历史行）：

`actor_id, action_type, resource_type, resource_id, before_snapshot, after_snapshot, timestamp, source, success, error_msg, prev_hash`

- `prev_hash`：上一条审计记录的 SHA-256，形成基础哈希链；
- `source` 取值：`agent / cli / api`。

**trace.jsonl 行字段**（面向大赛，与 audit_log 分开）：

`timestamp, type, actor, action, resource, detail, success, error_msg`

- `type` 枚举：`prompt, api_call, tool_call, workflow_run, human_intervene`；
- 每次拦截器触发，追加一行 JSON 到 `demo/output/trace.jsonl`；
- 人工干预通过 `log_human_intervene(desc, actor="human")` 写入 `human_intervene` 类型；**禁止手动编辑 trace 文件**。

**极简伪代码示例**：

```
def audit_interceptor(actor, action, resource, data, success=True, error_msg=None, trace_type="api_call"):
    rows = storage.get_sheet("audit_log")
    prev = rows[-1] if rows else None
    prev_hash = sha256(json.dumps(prev)).hexdigest() if prev else "0" * 64

    audit_row = {
        "actor_id": actor, "action_type": action,
        "resource_type": "sheet", "resource_id": resource,
        "before_snapshot": None, "after_snapshot": data,
        "timestamp": now_iso(), "source": "cli",
        "success": success, "error_msg": error_msg,
        "prev_hash": prev_hash,
    }
    storage.append_row("audit_log", audit_row)  # 只追加

    trace_line = {
        "timestamp": now_iso(), "type": trace_type,
        "actor": actor, "action": action, "resource": resource,
        "success": success, "error_msg": error_msg, "detail": data,
    }
    with open("demo/output/trace.jsonl", "a", encoding="utf-8") as f:
        f.write(json.dumps(trace_line, ensure_ascii=False) + "\n")
    # 若业务写操作抛错，外层捕获后以 success=False + error_msg 再走一次本函数
```

**补充说明**：

- `before_snapshot` / `after_snapshot`：更新类操作记录修改前后值，新增类操作 `before_snapshot` 为 `None`；
- trace 的 `type` 由 `trace_type` 参数传入（Agent 输入写 `prompt`，业务调用写 `api_call`），不硬编码；
- `log_human_intervene(desc, actor="human")` 生成 `human_intervene` 类型记录并带人工描述；
- 拦截器必须原子完成「写审计 + 写 trace」，任一失败要回滚并抛 `A001`。

### 3.3 权限引擎

**职责**：输入「主体 + 资源 + 操作」，返回允许 / 拒绝。

**预置 4 种角色权限矩阵**（写死，初赛不做动态配置）：

| 角色 | 读所有 Sheet | 写普通 Sheet | 写审计 / 规则表 | 管理成员 |
| --- | --- | --- | --- | --- |
| owner | ✅ | ✅ | ✅ | ✅ |
| admin | ✅ | ✅ | ✅ | ✅ |
| member | ✅ | ✅ | ❌ | ❌ |
| readonly | ✅ | ❌ | ❌ | ❌ |

**校验函数**：

```
def check_permission(actor_id: str, action: str, resource: str) -> bool:
    # resource 形如 "workbook" 或 "sheet:<name>"
    # 拒绝时抛 GXError("P001", "permission denied", module="perms", context={...})
```

- 团队权限继承：先按用户自身角色判定，未命中再按所属团队角色取并集；
- 拒绝时返回结构化错误，并写入审计 + trace（`success=false`）。

**判定规则**：

- `action` 枚举：`read` / `write` / `admin`；
- `resource`：`workbook` 表示组织级操作，`sheet:<name>` 表示单表操作；
- 判定顺序：用户自身角色 → 所属团队角色取并集 → 默认拒绝；
- 「写审计 / 规则表」只允许 owner/admin，业务代码不能绕过。

### 3.4 Rulesets 规则引擎

**职责**：在 PR 合并 / 写操作前校验，不通过则阻断并记审计。

**初赛只实现 2 条规则**：

1. **PR 合并需至少 1 个审批人**：`pull_requests` 中该 PR 审批人数量 ≥ 1；
2. **合并前需通过 required-check 工作流**：读取该 PR 最新一条 `workflow_runs` 记录，状态为成功才放行。

**校验函数**：

```
def evaluate_rules(pr_id: str, context: dict) -> list[RuleViolation]:
    # 返回违规列表，空列表表示通过
    # 存在违规时抛 GXError("R001", ...) 阻断操作
```

校验时机：执行 PR 合并动作前调用；失败原因写入审计，并返回给调用方。

**补充约定**：

- `RuleViolation` 字段：`rule_id`、`message`、`resource_id`；
- `context` 至少包含：PR 信息、审批人列表、最新 `workflow_runs` 记录；
- 规则按固定顺序执行，返回全部违规（不短路），便于一次看全问题；
- 无违规时放行；任一违规即阻断并记 `R001`。
