## 一、官方比赛与提交规则（已核实）

1. **提交物是 agent 快照，不是一次性 demo。** 平台注入临时 Key / 模型 / Base URL 等环境变量，包入口为 `main.py`，依赖由 `requirements.txt` 提供。
2. **同一份提交要跑完全部任务**（GitHub + Sheet），才会形成聚合榜分数；只跑一个任务不构成完整分数。
3. **seed 数据必须由应用自己 provision。** 官方明确写出：需求中出现账户、组织、团队、仓库、分支、文件、提交、议题、里程碑、PR、评审、权限关系等，都是「预置数据」，应用要在对应场景前把这些记录准备好，并用隔离的浏览器会话提供各账号。
4. **所有写操作必须服务端持久化 + 权限校验 + 原子完成。** 失败时不得产生半成品对象，也不得留下部分状态。
5. **判分以无障碍语义为准。** 需求里每一个引号内的名称都是「精确的英文 accessible name」，role / scope / observable-state 的描述是权威口径；视觉样式（看起来像 tab、像按钮）不改变 role 要求。
6. **每个原子需求都独立成立。** 即使某个 seed 配置不完整，原子需求仍然生效。
7. 明确排除范围：实时协作、Actions、Packages、Wiki、项目看板、通知投递、外部 Git 远程协议。

> 参考仓库（`aurasuisui/GOSIM-Create`）调研补充：hackathon 为 2 个任务、200 条测试、500 CNY 预算，截止 2026-10-17；官方 hackerthon 测试集不公开，`arc-bench-lite` 的同源任务只能作为本地部分 oracle。该仓库旧管线曾因请求预算闸门（单次 27k–121k 字符，超过 24000 上限）死在第一次 LLM 调用，**不要照抄其旧管线**。
