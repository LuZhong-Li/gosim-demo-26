# 提交与演示指南

> 提交前最后一步：填三项链接 + 录 Demo 视频。工程侧自检见 docs/plans/07-提交验收与提交物.md。

## 一、提交页三项链接

| 输入框 | 链接要求 | 怎么拿 |
| --- | --- | --- |
| GitHub 仓库 | 仓库主页 URL，不带末尾 `.git` | 仓库设为 **Public** 后，复制浏览器地址栏 |
| 生产轨迹 | `demo/output/trace.jsonl` 的 **Raw 原始链接** | 在 GitHub 打开该文件 → 点右上角 **Raw** → 复制地址栏；无痕模式能直接下载文本 |
| Demo 视频 | 公网可直接播放 | 上传 Bilibili / YouTube 等，复制公开链接 |

## 二、演示前准备

```powershell
# 仓库根目录，激活虚拟环境
.venv\Scripts\activate
python tools/check_env.py
```

## 三、Demo 视频录制脚本（全自动，约 1-2 分钟）

> 初赛推荐：全自动脚本演示，trace 完全校验通过且包含 human_intervene。
> OBS 只录 3 条核心命令，trace 输出与视频操作一一对应，不会事件混杂。

1. 重置干净环境（OBS 从这里开始录）

```powershell
python demo/init_seed.py
```

作用：重置种子工作簿，并清空旧的 trace。

2. 运行完整 Agent 演示脚本（核心执行过程）

```powershell
python demo/run_demo.py
```

脚本自动依次完成：创建只读成员 -> 创建 PR -> 无权限用户创建 PR（P001 权限拒绝）
-> Rulesets 规则拦截（R001）-> PR 审批 -> 运行 ci-check 工作流 -> PR 合并
-> 写入 human_intervene 人工干预事件。

3. 校验生产轨迹

```powershell
python tools/check_trace.py
```

预期输出：

```text
[OK] trace 校验通过: demo\output\trace.jsonl
```

录制范围：从 `init_seed` 执行开始，到 `check_trace` 打印 OK 结束。
口播开场一句项目定位即可，过程中可简要点出“脚本自动完成成员、权限、规则、工作流、审计全链路”。

## 四、录完后的收尾

录制已生成最终 `demo/output/trace.jsonl`；`init_seed` 会重写种子工作簿（仅时间戳变化），提交前处理：

```powershell
git status
git restore demo/seed-workbook.xlsx   # 撤销 init_seed 引起的时间戳变化
git add demo/output/trace.jsonl
git commit -m "chore: 更新最终演示 trace"
git push origin main
```

> 这样视频里展示的 trace 与最终提交的 Raw 链接内容一致。
