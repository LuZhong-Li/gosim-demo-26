# 提交与演示指南

> 提交前最后一步：填三项链接 + 录 Demo 视频。工程侧自检见 docs/plans/07-提交验收与提交物.md。

## 一、提交页三项链接

| 输入框 | 链接要求 | 怎么拿 |
| --- | --- | --- |
| GitHub 仓库 | 仓库主页 URL，不带末尾 `.git` | 仓库设为 **Public** 后，复制浏览器地址栏 |
| 生产轨迹 | `demo/output/trace.jsonl` 的 **Raw 原始链接** | 在 GitHub 打开该文件 → 点右上角 **Raw** → 复制地址栏；无痕模式能直接下载文本 |
| Demo 视频 | 公网可直接播放 | 上传 Bilibili / YouTube 等，复制公开链接 |

## 二、演示前准备

```powershell
# 仓库根目录，激活虚拟环境
.venv\Scripts\activate

# 重置种子，并确认环境就绪
python demo/init_seed.py
python tools/check_env.py
gx --help
```

## 三、Demo 视频录制脚本（约 3-4 分钟）

建议录制顺序与口播要点：

| 时间 | 环节 | 命令 | 口播 / 字幕要点 |
| --- | --- | --- | --- |
| 0:00 | 开场 | — | 项目名 + 一句话定位：用本地 xlsx 模拟 GitHub 组织权限、Rulesets、审计、工作流 |
| 0:15 | 启动 | `python tools/check_env.py`；`gx --help` | 无需任何 API 密钥，本地即可运行 |
| 0:45 | 成员管理 | `gx member list`；`gx member add bob member`；`gx member list` | 以表格为数据源，成员可见、可增改 |
| 1:20 | 权限拦截 | `gx --actor 2 member add eve member` | 用 member 身份（alice）执行管理操作，预期被拒 P001 |
| 1:50 | 创建 PR | `gx pr create --title "demo change"`；`gx pr list` | PR 模拟记录落表 |
| 2:05 | 规则拦截 | `gx pr merge 1` | 无审批人合并，预期被 Rulesets 拦截 R001 |
| 2:30 | 审批 | `gx pr approve 1 alice` | 补审批人 |
| 2:45 | 工作流 | `gx workflow list`；`gx workflow run ci-check` | 执行 ci-check，得到 success 运行记录 |
| 3:00 | 合并 | `gx pr merge 1` | 规则满足后合并成功，状态变为 merged |
| 3:15 | 审计与 trace | `python tools/debug_helper.py demo/seed-workbook.xlsx audit_log --latest 10`；`python tools/check_trace.py demo/output/trace.jsonl`；`Get-Content demo/output/trace.jsonl` | 展示审计哈希链与 trace.jsonl 留痕 |
| 3:45 | 收尾 | — | 一句话总结完整闭环，并指向三个提交物位置 |

口播可参考的自然语言演示（可选加一段）：

```powershell
python agent/mock_nl_parser.py "添加成员 bob 为 member"
python agent/mock_nl_parser.py "运行工作流 ci-check"
```

## 四、录完后的收尾

录视频期间会改动种子和 trace，提交前请重置到干净状态：

```powershell
python demo/init_seed.py        # 重置种子工作簿
python demo/run_demo.py         # 重新生成最终 demo/output/trace.jsonl
python tools/check_trace.py demo/output/trace.jsonl
git status
git add demo/output/trace.jsonl
git commit -m "chore: 更新最终演示 trace"
git push origin main
```

> 这样视频里展示的 trace 与最终提交的 Raw 链接内容一致。
