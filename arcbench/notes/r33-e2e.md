# r33 真实浏览器回归（2026-09-30）

第三轮修复的端到端验证。用 Chromium 直接访问真实后端 + 构建产物，不复用任何 mock。

## 为什么要跑这一步

jsdom 单测用的是合成事件，**测不出"网格单元格本身就是 `<input>`"这类问题**。
本轮就是靠这一步抓到了一个真 bug：`Ctrl+C/V` 的守卫按 `tagName === 'INPUT'`
把网格当成文本域，键盘复制粘贴在真实浏览器里完全不可达（单测却是绿的，
因为 jsdom 点击 `<td>` 不会把焦点交给内层 input）。

## 用例与结果

GitHub（`arcbench/notes/github-r33-regression.spec.ts`，4/4，连跑两次稳定）

1. 登录后能浏览种子组织与仓库（Code / Issues / Pull requests / Settings 均为链接）；
2. 议题详情：Labels / Assignees 勾选面板可用，改动落入活动时间线，刷新后仍在；
3. PR：Conversation / Commits / Files changed 链接、普通会话评论、聚合 diff、
   提交短哈希 → 该修订 diff；
4. 访客打开私有仓库得到 `Access denied`。

Sheet（`arcbench/notes/sheet-r33-clipboard.spec.ts`，4/4，连跑三次稳定）

1. `Ctrl+C` + `Ctrl+V` 在同表内复制单元格；
2. 工具栏 `Undo` / `Redo` 按钮反转并重放一次编辑；
3. 真实 `paste` 事件携带 TSV 后，从活动单元格铺开整个矩形（含空列）；
4. 行号 / 列头右键菜单给出 `role="menuitem"` 命令。

## 复现方式

```powershell
# 1. 构建前端
cd arcbench/agent/templates/github/frontend; npm run build
cd ../../../sheet/frontend; npm run build

# 2. 起后端（种子在启动时 provision）
cd ../github/backend; $env:PORT=3301; node src/index.js
cd ../sheet/backend;    $env:PORT=3302; node src/index.js

# 3. 跑 Playwright（spec 副本需放在 arcbench/upstream/smoke/ 下，
#    否则 @playwright/test 解析不到）
Copy-Item arcbench/notes/github-r33-regression.spec.ts arcbench/upstream/smoke/github/r33-regression.spec.ts -Force
Copy-Item arcbench/notes/sheet-r33-clipboard.spec.ts   arcbench/upstream/smoke/sheet/r33-clipboard.spec.ts -Force

cd arcbench/upstream
$env:TARGET_URL='http://127.0.0.1:3301'
node node_modules/@playwright/test/cli.js test --config ../notes/r33-regression.config.cjs --workers 1 --reporter list
$env:TARGET_URL='http://127.0.0.1:3302'
node node_modules/@playwright/test/cli.js test --config ../notes/r33-sheet.config.cjs --workers 1 --reporter list
```

## 写用例时的两个坑（供后续参考）

- 网格单元的值在**内层 input**里（`aria-label="Cell A1"`），要用 `toHaveValue`；
  外层 `gridcell` 的 accessible name 才是坐标，且必须 `exact: true`，
  否则 `name: 'A1'` 会同时命中 `A10`…`A19`。
- 提交 id 是 `c` + base36（如 `cmunn1b`），不是十六进制。
