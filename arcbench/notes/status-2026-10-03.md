## 四、问题现状：三类失败 + 一个总瓶颈

### 总瓶颈：**世界没被播种（P9）**

评测场景的 GIVEN 依赖预置数据（账号 / 组织 / 团队 / 仓库 / 文件 / issue / PR）。
生成的 app 自己那份 `seed.js` 常常跑不起来（调了 store 里不存在的方法、或自家 store 形状不匹配），
我们注入的播种器又常常**拿不到可用登录态**，于是世界是空的 → 所有需要预置数据的场景第一步就失败 → 0 分。

这解释了为什么"能起服务"和"能得分"之间隔着一条鸿沟：r80/r81/r82 都有任务成功 `Backend listening`，
但分数仍然是 0。

### P9 的已知细节

```
[arc-agent]  sign-in store not seeded: ['backend/src/app.js: unsupported password hashing', ...]
[rehearsal]  seeded sign-in probe: the seeded account signs in      ← 注入的登录路由是通的
```

## 六、平台操作坑（今天踩全了）

1. **Run 按钮在提交保存后 3–5 分钟内假死**；点击报 `Timed out running CDP command Input.dispatchMouseEvent`
   **不代表没生效**，也不能只看 `/running` 的瞬时值 —— 以历史页里该 snapshot 的 "running" 标记为准；
2. **页面会半加载很久**（历史页常常要 20–60 秒才出现 `New submission` / `History (n)`），自动化必须重试循环；
3. **登录态会失效**，失效时页面上只有 `Confirm your team before entering / Sign in to continue` —— 需要人工重新登录；
4. run 页时间戳是 **UTC**，换算北京时间 +8；
5. **禁止删除操作**（rm / git reset / checkout --），新目录带时间戳、新 zip 用新文件名；
