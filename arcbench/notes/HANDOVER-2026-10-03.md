## 3. 平台规则（必须知道）

| 规则 | 细节 |
|---|---|
| 榜单取**最后一次保存的提交** | 新上传的提交立刻成为最新；旧提交的 run 成绩不继承 |
| 同一提交内允许多次 run | 平台自动保留最高分 run |
| 新提交**不继承**旧提交的分数 | 每次上传都是全新开始 |
| 全 0 提交可以删除 | 或直接重新上传保险包作为新提交 |
| 容器内存 2GB | Playwright 默认 4 workers，OOM 会 SIGKILL（exit 137） |
| Playwright 用例超时 10s | 整条 scenario 超时 60s |
| `.arc/` 是运行期产物 | **提交 zip 禁止携带** |
| 合规边界 | 优化信号只能来自 requirements 文本；不能硬编码测试断言；不能把 Playwright spec 喂给 agent |
| 时间戳 | run 页显示 **UTC**，+8 = 北京时间 |
| Run 按钮 CDP 超时 | 报错 ≠ 没生效；等 3-5 分钟看历史页 |
| project.zip 不含 playwright report | 我们只能拿到 `test pass (x/200)` 一个总数；逐条结果只能靠自测站 |
| 自测站 | `arcbench-selftest-web.vercel.app`，跳过 agent 直接测产物；剩 2 次配额，每天 8:00 重置 |

## 5. 最重要的教训（按价值排序）

### 5.1 守卫把失败藏起来，比不加守卫更危险

这是整个项目最深刻的教训。我们加了大量守卫防崩溃：
- `ensure_store_method_stub` 的 Proxy 兜底：所有未定义方法返回空值
- `create/add/delete → () => undefined`：写操作变 no-op
- `is*/has*/can* → () => true`：鉴权永远通过
- `__arcStubModule`：seed.js 崩了也不影响 listen

**结果**：应用能启动、能应答、日志全绿、POST 返回 201——但 store 里什么都没有，测试读到空，0 分。日志看起来成功，实际空壳。

**r84 的转向**：从"防崩"改成"让失败可见"：
- 缺失写方法 → console.error + 抛错（变 500 响应，不崩进程）
- 缺失谓词 → 返回 false（fail closed），不再让反向断言白过
- 播种器每次写后回读 → `[arc-seed] verify /api/repos -> 200 items=0 (the write did not persist)`

### 5.2 "绿"信号不预测得分

| 信号 | 实际意义 |
|---|---|
| `Backend listening` | 端口开了，不代表路由对 |
| `world seed finished` | 播种流程跑完了，**不代表写进去了** |
| `rehearsal green` | r73 Stage-2 rehearsal 8/8 红，拿了 5.35；绿 rehearsal 拿 0 |
| `exact-name coverage 158/178` | 字符串包含判断，不预测测试通过 |
| `npm run build ✓` | `_placeholder_export` 塞空桩也能构建通过 |

**结论**：唯一可靠的分数信号就是平台返回的 `test pass (x/200)`。其他都是必要不充分条件。

### 5.3 平台不给逐条用例结果

- run 页 Stdout tab 在评测开始前截断
- project.zip 里没有 playwright report
- `.arc/` 目录里只有 preflight/runner-events/traceability，没有 report.json
- **我们永远只有总分一个数字**

要拿逐条结果，只能用自测站 `arcbench-selftest-web.vercel.app`（但之前 0/30 整条 60s 超时，与本地 200 正常存在环境差异）。

### 5.4 时间戳与操作

- run 页时间是 UTC，+8 = 北京
- Run 按钮报 CDP 超时但实际生效——等 3-5 分钟看历史页
- pnpm 打包必须 `--node-linker=hoisted`，否则 zip 里有 `../` 软链路径被安全校验拒绝
- Compress-Archive 丢空目录项，用 Python `zipfile` 手动打包

## 8. 收尾规则（重要）

1. **保险包是底线**：任何时候如果最新提交全 0，立刻重新上传 `arc-agent-r33.zip`（￥0 / 20 分钟），把 9.65 锁回最新提交。
2. **Running≠0 不上传**：等所有 run 归零再传新包。
3. **新包上传后必须人工点 Run**：平台不会自动跑，CDP 超时也可能实际生效。
4. **预算止损线 ¥40**：低于此线停止生成型实验，只保保险包。
5. **提交包不能带 `.arc/`**：那是运行期产物。
