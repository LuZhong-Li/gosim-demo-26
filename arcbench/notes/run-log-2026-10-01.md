# ARC-Bench 提交与失败日志（2026-10-01 及前一晚）

平台每个 run 都永久保留自己的页面（`https://arc-bench.com/runs/<run-id>`），
里面 Status 面板分三个 STAGE，**Stdout** 页签是完整日志。这份文件把每轮的
成绩与**确切报错行**抄下来，避免证据只留在对话里。

## 快速查日志的方法

- run 页 → 左侧 `Status` 看三个 STAGE（哪一步 Failed）。
- run 页 → `Stdout` 页签（本机自动化用
  `getByText("Stdout", {exact:true}).press("Enter")` 能点开）看完整日志。
- 关键词：`[arc-agent]`（我们 agent 的输出）、`[rehearsal]`、`[selfcheck]`、
  `[frontend-npm-build.stdout]`、`[backend-npm-install.stdout]`、
  `[template-app.stdout]`。
- 消息中心（右上角铃铛）会写一句话结论，例如
  `Your run failed: Runner exited with test failures or runtime errors`。

## 平台硬规则（踩过的坑）

1. **一个任务同时只能有一个 run**，而且这条是**跨提交生效**的：上一版的
   GitHub run 还在 Running 时，新提交的 GitHub run 起不来（r53 就只起了
   Sheet，GitHub 要等 r52 记录关闭后手动点 `Run latest submission` 才起）。
2. **Run 必须用最新快照**：新提交会让旧提交变 `Superseded`，旧提交再也起不了 run。
3. agent 非零退出时，平台**会自动重试**（r50 重试了 3 次，token 累计到 57.8 万）。
