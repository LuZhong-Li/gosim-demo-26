# ARC-Bench 提交与失败日志（2026-10-01 及前一晚）

平台每个 run 都永久保留自己的页面（`https://arc-bench.com/runs/<run-id>`），
里面 Status 面板分三个 STAGE，**Stdout** 页签是完整日志。这份文件把每轮的
成绩与**确切报错行**抄下来，避免证据只留在对话里。

## 快速查日志的方法

- run 页 → 左侧 `Status` 看三个 STAGE（哪一步 Failed）。
- run 页 → `Stdout` 页签（本机自动化用
  `getByText("Stdout", {exact:true}).press("Enter")` 能点开）看完整日志。
- 关键词：`[arc-agent]`（我们 agent 的输出）、`[rehearsal]`、`[selfcheck]`、
  `[frontend-npm-build.stdout]`、`[backend-npm-install.stdout]`、
  `[template-app.stdout]`。
- 消息中心（右上角铃铛）会写一句话结论，例如
  `Your run failed: Runner exited with test failures or runtime errors`。

## 平台硬规则（踩过的坑）

1. **一个任务同时只能有一个 run**，而且这条是**跨提交生效**的：上一版的
   GitHub run 还在 Running 时，新提交的 GitHub run 起不来（r53 就只起了
   Sheet，GitHub 要等 r52 记录关闭后手动点 `Run latest submission` 才起）。
2. **Run 必须用最新快照**：新提交会让旧提交变 `Superseded`，旧提交再也起不了 run。
3. agent 非零退出时，平台**会自动重试**（r50 重试了 3 次，token 累计到 57.8 万）。

## 每轮的确切死因

### r49 — 评测机构建失败

```
[frontend-npm-build.stdout] > vite build
[frontend-npm-build.stdout] ✓ 19 modules transformed.
[frontend-npm-build.stderr] ✗ Build failed in 382ms
[frontend-npm-build.stderr] Could not resolve "./pages/RegisterPage" from "src/App.tsx"
```

STAGE 2 反复出现
`Command '['npm', 'run', 'build']' returned non-zero exit status 1.`
100 条用例一条没跑。

### r50 — 我们自己的 agent 崩溃

```
[arc-agent] model generation done: files=45 covered=43 calls=10 tokens=377964
[arc-agent] failed: [Errno 36] File name too long:
  '/workspace/template/frontend/src/pages/../pages/../pages/…（重复 448 次）…/PullRequestDetailPage.tsx'
```

模型吐出一条 4197 字符的退化 import，`Path.exists()` 在 Linux 上直接抛
`OSError(36)`，异常冒到 `main()` 顶层 → agent 退出码 1 → 平台重试 3 次全崩，
产物不完整。

### r51 — 具名导出不存在，Rollup 拒绝打包

```
[frontend-npm-build.stdout] ✓ 132 modules transformed.
[frontend-npm-build.stderr] ✗ Build failed in 1.60s
[frontend-npm-build.stderr] src/pages/ManageAccess.tsx (4:9):
  "Page" is not exported by "src/components/Form.tsx", imported by "src/pages/ManageAccess.tsx".
[frontend-npm-build.stderr] 4: import { Page, Section, Button, Field, SelectField, FormError } from '../components/Form';
```

我们的演练循环跑了 4 次（`deterministic repair` 修好了一个语法坏文件
`CodeTreePage.tsx`，两次模型修复各写 1 个文件），全部撞同一条错，最后
`[rehearsal] giving up; submitting as-is`。根因是 `complete_missing_exports()`
找目标文件时提前 `break`，没试到 `frontend/src/components/Form.tsx`。

### r52 — app 起来了，但用例全挂

评测侧首次成功：

```
[frontend-npm-build.stdout] ✓ 102 modules transformed.
[frontend-npm-build.stdout] ✓ built in 2.73s
[frontend-npm-install.stdout]  ...
[template-app.stdout] Backend listening at http://127.0.0.1:3000
[generation-agent.stdout] [rehearsal] app builds and starts cleanly in 37s
```

但 STAGE 3 = `Failed`，消息中心：
`Your run failed: Runner exited with test failures or runtime errors` →
两题都是 0/100。

**结论（本轮最重要的发现）**：两道题的场景都从一份**预置世界**开始，而生成的
app 一条都没预置：

- GitHub 需求包 124 处写着
  `the seeded data is account alice-dev, email alice.dev@example.test, password Valid-password-123!`，
  并要求 *"The application must provision those records before the corresponding
  scenario"*；另外还有 `organization Acme Demo`、`repository acme-docs` /
  `secret-research`、`member bob-reviewer`、`team frontend-team`、
  `branches main 和 feature-search`。
- Sheet 需求包用另一种句式（`seeded` 出现 400 次、`Q3 Sales` 322 次）：
  `The evaluation seed contains the seeded workbook Q3 Sales, worksheet Sheet1, and cell A1 value Region`。

测试第一步就是"用 alice-dev 登录" / "点击 Q3 Sales 工作簿"，所以一步断、
100 条连锁全挂——这解释了"app 能构建、能启动、却 0 分"。
