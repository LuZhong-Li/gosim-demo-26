# ARC-Bench 提交与失败日志（2026-10-01 及前一晚）

平台每个 run 都永久保留自己的页面（`https://arc-bench.com/runs/<run-id>`），
里面 Status 面板分三个 STAGE，**Stdout** 页签是完整日志。这份文件把每轮的
成绩与**确切报错行**抄下来，避免证据只留在对话里。

## 快速查日志的方法

- run 页 → 左侧 `Status` 看三个 STAGE（哪一步 Failed）。
- run 页 → `Stdout` 页签（本机自动化用
  `getByText("Stdout", {exact:true}).press("Enter")` 能点开）看完整日志。
- 关键词：`[arc-agent]`（我们 agent 的输出）、`[rehearsal]`、`[selfcheck]`、
  `[frontend-npm-build.stdout]`、`[backend-npm-install.stdout]`、
  `[template-app.stdout]`。
- 消息中心（右上角铃铛）会写一句话结论，例如
  `Your run failed: Runner exited with test failures or runtime errors`。

## 平台硬规则（踩过的坑）

1. **一个任务同时只能有一个 run**，而且这条是**跨提交生效**的：上一版的
   GitHub run 还在 Running 时，新提交的 GitHub run 起不来（r53 就只起了
   Sheet，GitHub 要等 r52 记录关闭后手动点 `Run latest submission` 才起）。
2. **Run 必须用最新快照**：新提交会让旧提交变 `Superseded`，旧提交再也起不了 run。
3. agent 非零退出时，平台**会自动重试**（r50 重试了 3 次，token 累计到 57.8 万）。

### r50 — 我们自己的 agent 崩溃

```
[arc-agent] model generation done: files=45 covered=43 calls=10 tokens=377964
```

### GitHub — 新回归：后端启动即崩，登录探针没跑成

```
[arc-agent] the backend now seeds that account through its own registration route:
            ['backend/src/index.js -> /api/auth/register']   ← 自注册钩子找到了路由（好事）
[rehearsal] startup rehearsal 1 (smoke port 3100)
[rehearsal] FAILED in 35s: backend `npm start` exited early (rc=1):
[arc-agent] repair turn wrote 1 file(s)
[rehearsal] startup rehearsal 2 → FAILED in 5s (rc=1)
[arc-agent] repair turn wrote 1 file(s)
[rehearsal] startup rehearsal 3 → FAILED in 5s (rc=1)
[rehearsal] giving up; submitting as-is            ← 出现
[selfcheck] exact-name coverage: 136/173 present (37 missing)
```

`[rehearsal] seeded sign-in probe: ...` **根本没跑**（后端没起来，探针在后端
bind 端口之后才执行）。真正死因（平台侧 `template-app.stderr`）：

```
PathError [TypeError]: Unexpected ( at index 46: /api/repos/:owner/:repo/file/:branch/:filePath(.*)
    at pathToRegexp (path-to-regexp/dist/index.js:274)
    at new Layer (router/lib/layer.js:93)
    at Function.route (router/index.js:428)
```

即生成的后端 `files.js` 用了 **Express 4 的旧正则参数语法 `:filePath(.*)`**，
而脚手架是 Express 5（`path-to-regexp@8`）直接拒掉 → 进程 rc=1。三轮演练 +
两次模型修复都没改对这个（模型每次只写 1 个文件且没定位到路由），所以
"submitting as-is"。附带还发现 `seed.js` 是 `require` 与 `export` 混写的坏文件
（`export async function seed()`），但它没被 `app.js` 引到，不是本次崩因。

结论：自注册种子钩子本身是好的（找到 `/api/auth/register` 并注入成功），
被一个**确定性、可机械修复**的 Express 路由语法问题挡在前面。
